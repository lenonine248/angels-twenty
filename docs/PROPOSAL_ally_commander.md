## 0. 結論を先に

**司令官AIそのものは、もう「自軍側」でも動いている。** ベンチ（`tools/bench.js:91`）はプレイヤーの席に
`new Commander(w, w.playerSide, mission)` を座らせて、自軍機を全部動かしている。敵側も §73 で同じクラスを動かしている。

足りないのは**「陣営」と「指揮系統」の区別**のほう。いまのコードは「自軍＝プレイヤーが動かすもの」として
`side === playerSide` で判定している所が多く、**同じ青の中に「プレイヤーの機体」と「友軍AIの機体」が並ぶ**ことを想定していない。
なので仕事の中心は次の3つになる。

1. ユニットに**指揮系統 `owner`**（`'player'` / `'ally'`）を持たせ、司令官AIが `owner` で自分の機体を選ぶ。
2. `side === playerSide` と書いてある所を1か所ずつ見て、**「陣営の意味で読んでいるのか、指揮の意味で読んでいるのか」**で分ける
   （勝敗・評価・ポイント・選択・一覧・色）。
3. 地上戦は**部品はある**（自軍の地上部隊・地上同士の射撃・`attackTag` での前進）が、
   「攻めあう」を作るには**前進／保持／後退の行動と、地上を撃つ地上兵器**が足りない。

## 2. 指揮系統を分ける `[A1]`

### 2.1 データ

- ユニットに **`owner`** を足す。`'player'`（既定）/ `'ally'`。敵側は持たない（＝陣営全体が1つの指揮）。
- ステージ定義では**自軍の機体・地上部隊・飛行場ごとに `owner: 'ally'`** と書く。書かなければ今までどおりプレイヤーのもの。
- 友軍の目標は **`stage.ally.objectives`**（敵の `stage.enemy.objectives` と同じ形、勝敗を持たない `SideObjectives`）。
- 友軍の練度は **`stage.ally.skill`**（敵の `enemy.skill` と同じ意味。既定 1）。

```js
friendly: {
  aircraft: [
    { type: 'F-2', name: 'HAMMER 1', loadout: [...] },                       // プレイヤー
    { type: 'F-1', name: 'EAGLE 1', owner: 'ally', x, z, agl, loadout: [...] }, // 友軍
  ],
  ground: [
    { type: 'TANK', name: '第1戦車隊', owner: 'ally', x, z, attackTag: 'enemy-armor' },
  ],
},
ally: {
  objectives: [ { type: 'destroyAll', tag: 'enemy-armor' } ],
  skill: 1,
  triggers: [ ... ],   // §5
},
```

### 2.2 司令官AI

- `Commander(world, side, mission, { owner })`。`_myAircraft()` は `owner` が渡されたとき**その指揮の機体だけ**を返す。
  渡さなければ今までどおり陣営全体（＝敵側と既存のベンチは1行も変わらない）。
- 友軍の司令官は `new Commander(world, SIDE.BLUE, allyPlan, { owner: 'ally' })`。**`stage.ally` を書いた面だけ動く。**
- ベンチ（プレイヤーの席）は `{ owner: 'player' }` にする。**友軍の機体をベンチが動かしてはいけない**（それは友軍の司令官の仕事）。

### 2.3 同じ陣営として共有するもの・分けるもの

| もの | 扱い | 理由 |
|---|---|---|
| 探知（コンタクト） | **共有**（`contactsFor(BLUE)` のまま） | 同じ陣営のデータリンク。分けると検出・記憶の仕組みを二重に持つことになる |
| パイロットの目標の重複回避・§85 の撃ちすぎ判定 | **共有**（陣営で数える） | 友軍機がプレイヤーの機体の狙う相手に重ねて撃たないようにする |
| 護衛の相手 | 友軍の戦闘機は**プレイヤーの攻撃機も護衛候補に入れる**（面ごとに切れる `ally.escortPlayer`） | 「友軍戦闘機と一緒に戦う面」の中心の動き。逆（プレイヤーの機体が友軍を自動で護衛する）はしない —— プレイヤーの機体は人が動かす |
| 対地目標の割り振り | `_pickGround` の「すでに向かっている機数」を**陣営で数える** | 友軍の攻撃機がプレイヤーの攻撃機と同じ目標に群がらない |
| 兵装ポイント | **友軍はプレイヤーの財布から引かない**（予算は無限＝敵と同じ） | 友軍の積み直しでプレイヤーの弾が買えなくなるのは理不尽 |
| 司令部の記録 `_plots` | 司令官ごと（分ける） | 司令官の持ち物。プレイヤーには司令官が無い |

### 2.4 `playerSide` を読んでいる所の仕分け

**1か所ずつ「陣営の意味か、指揮の意味か」を決める。** 一括置換はしない（§42〜§44 と同じ罠 ——
「どの種類の実装か」で絞ると漏れる。「その判定が何を表しているか」で切る）。

| 判定 | 意味 | 友軍を入れるか |
|---|---|---|
| 選択・指示・一括設定（`commands.js`） | 指揮 | **入れない**（選べない。理由は「友軍（指揮外）」と出す —— `commandable` の経路を使う） |
| 下の一覧（`hud.js:308`） | 指揮 | 分けて表示（友軍は別の段・操作不可） |
| 敗北「全機を失った」（`mission.js`） | 指揮 | **入れない**（Q3 決定） |
| 敗北「全飛行場を失った」 | 指揮 | 共用の飛行場は数える・友軍専用は数えない（§2.6） |
| 評価の練度 | 指揮 | **入れない**（Q3 決定） |
| 積み直しの予算（`_needsRearm`） | 指揮 | 入れない（§2.3） |
| 最後の一撃（空にある自軍の弾） | 指揮 | 入れない（プレイヤーの弾だけで保留する） |
| 探知・霧・敵の印の見え方 | 陣営 | 入れる |
| 撃墜の記録・ログの色 | 陣営 | 入れる（ログは頭に `[友軍]`） |

### 2.5 見た目

- 地図・3D の印は、**友軍の航空機だけ緑**（Q7 決定）。友軍の地上部隊は自軍と同じ青。
- 一覧・ブリーフィングに「友軍」の欄を立てる（何を積んで何をしに行くか）。
- 友軍の司令官の判断はログに短く出す（「[友軍] EAGLE 1 HAMMER 1 の護衛に付きます」）。**出しすぎない** —— 2秒ごとに同じ文を出さない（変わったときだけ）。
- リプレイは `owner` を記録する（色を再現するため）。記録の形式の版を上げる。古い記録は `owner` 無し＝プレイヤーとして開く。

### 2.6 飛行場

- 友軍機は**空中で出現**するか、**飛行場から出る**。飛行場は**プレイヤーの飛行場を共用できる**（2026-09-27 決定）。
  友軍専用の飛行場（`owner: 'ally'`）も置ける。
- **友軍機は整備枠の制限を受けない**（2026-09-27 決定）。整備枠（`serviceSlots`・2つ）の待ち行列に並ばず、
  着陸したら枠の外で並行して整備される —— **プレイヤーの積み直しが友軍に遅らされることは無い**。
  実装: `airbase.js` の待ち行列（`queue` → `slots`）に入れず、友軍機だけの整備の列を別に回す（整備の手順 `buildServicePlan` と時間は同じ）。
- 友軍の積み直しの兵装は `plannedLoadout`（離陸時の搭載）をそのまま戻す。ポイントは引かない（§2.3）。
- 友軍の増援は敵の増援（`{every, first, max, ...}`）と同じ書き方で飛行場に付けられる。
- **確かめること:** 滑走路の発着に順番待ち（離陸・着陸の間隔）があるなら、そこも友軍がプレイヤーを待たせないか見る（未確認）。
- 自軍の飛行場が全部落ちたときの敗北は、**プレイヤーの機体が使える飛行場**で数える
  （共用の飛行場は数える・友軍専用の飛行場は数えない）。

## 3. 地上戦 `[A3]`

### 3.1 いま足りないもの

1. **撃ちあう地上兵器がほとんど無い。** 地上を撃てるのは自走榴弾砲と車両の機銃だけ。戦車のような「地上部隊の主力」が無い。
2. **行動が「巡回」か「最寄りへ寄って止まる」しかない。** 前線を押し上げる・持ち場を守る・下がる、が書けない。
3. 空からの支援が**効く釣り合い**になっているかを測る道具が無い。

### 3.2 足すもの

- **地上ユニットの種類 `TANK`（戦車）**（Q6 決定）。性能は §3.2.1。
- **地上の行動**（`groundMode`）:
  - `advance` —— `attackTag` の敵へ寄る（いまの動き）
  - `hold` —— その場（または指定点）に留まり、射程に入った敵を撃つ
  - `route` —— 経路をたどる（いまの巡回）
  - `retreat` —— 指定点へ下がる
- 地上の行動は**ステージ定義とトリガーで切り替える**（§5）。地上に司令官AIは付けない（→ 3.3）。
- 地上は今までどおり**探知を通さず、ステージが与えた情報で動く**（`_advanceGoal` の約束を変えない）。

### 3.2.1 地上移動ユニットの役割と性能 `[役割は決定・数値は案]`

**役割（2026-09-27・プレイヤーの決め）:**

| | 速度 | 攻撃力 | 耐久 | 仕事 |
|---|---|---|---|---|
| CONVOY 車両部隊 | 高 | 低 | 低 | 偵察・遊撃 |
| TANK 戦車（新） | 低 | 中 | 高 | 正面から攻める。前線の要 |
| ARTILLERY 自走榴弾砲 | 低 | 高 | 中 | 前線の少し後ろから砲撃する。敵にいれば優先して壊したい相手 |

**いまの車両部隊と榴弾砲は、この役割にほぼ合っている。** 車両部隊は既に最も速く（12m/s）・最も脆く（hp 110）・
1発が最も弱い（機銃 1.2〜2.4）。榴弾砲は1発が最も重い（55〜70）。**足りないのは戦車と、3種の間の「相性」のほう。**

#### 相性 —— 1対1で誰が誰に勝つか

役割をそのまま数値にすると「速い・弱い・脆い」は単に弱い部隊になる。役割を**相性**に置き換えると、
3種が互いを必要とする形になる:

```
  車両部隊 ──(速さで詰めて機銃)──▶ 榴弾砲 ──(射程の外から砲撃)──▶ 戦車 ──(装甲で機銃を弾く)──▶ 車両部隊
```

- **戦車 ＞ 車両部隊** —— 機銃は装甲に弾かれる。主砲は直射で、速く動く相手にも当たる。
- **榴弾砲 ＞ 戦車** —— 戦車の主砲（2.5km）の外（4.5km）から一方的に撃てる。遅い戦車は詰めるあいだに削られる。
- **車両部隊 ＞ 榴弾砲** —— 山なりの弾は飛翔が長く（4.5km で約20秒）、速い車両には当たりにくい。
  寄られると榴弾砲は短い機銃しか無い。＝**遊撃の仕事**。
- **空 ＞ 全部**。どれも上からは弱い（対空は車両部隊・榴弾砲の短い機銃だけ、戦車は無し）。
  空を止めるのは敵の対空砲・SAM と敵の戦闘機。

これで「敵の榴弾砲を優先して壊したい」は**空と車両部隊の2通りの答え**を持ち、
「前線の要」の戦車は**榴弾砲に守られた形でしか前に出られない**（戦車だけで進むと榴弾砲に削られる）。

#### 数値の案

| | 速度 | hp | 装甲 | 主な武器 | 対空 |
|---|---|---|---|---|---|
| CONVOY | 12 → **16**（案） | 110（今のまま） | 0 | 機銃 800m・1.2〜2.4/発・5発/秒 | 機銃（今のまま） |
| TANK | **8** | **250** | **3** | 主砲 2.5km・直射・40〜50/発・6秒に1発 | なし |
| ARTILLERY | 9（今のまま） | 200（今のまま） | 0 | 榴弾 4.5km・55〜70/発・8秒に1発（今のまま） | 機銃（今のまま） |

- **装甲 `armor`（新）**: 弾1発ごとに一定量を引く（弾丸だけ・爆風とミサイルには効かない）。
  車両部隊の機銃（1.2〜2.4）は戦車に 0 になり、主砲・榴弾・爆弾・AGM は素通り。
- **戦車の hp 250 は空から見た固さで決めた**: 爆弾（260）の直撃1発・AGM（180）2発で落ちる。
  地上同士では榴弾 4〜5発。**空の支援の値打ちを残すため、空に対して固くしすぎない。**
- **車両部隊の速度を上げる案（12→16）** は「速さで榴弾砲に詰める」ために入れた。
  既存の面（COASTAL WALL の「沿岸レーダーに着く前に倒す」）の時間が縮むので、上げるならその面を測り直す。
- **自機の機銃で戦車を掃射しても効くか**は、機銃1発の威力と装甲 3 の比べ合いになる（未確認・測る）。

#### 詰め方

1. `tools/_groundwar.js` に**1対1の総当たり**を入れる（3種×3種・距離 6km から・種を固定）。
   出すのは勝った側・決着の秒・勝った側の残り hp。
2. 目標の表: 上の相性で**勝つ側が 8割以上**、決着が **60〜240秒**（空の支援が間に合う長さ）。
3. 合わなければ数値を回す。**先に回すのは戦車（新しいもの）で、今ある2種はなるべく動かさない**（既存の面のベンチが動くため）。
4. 最後に**混成どうし**（例: 戦車3＋榴弾砲2＋車両2 対 同じ編成）で、決着が種で散らばるか（一方的にならないか）を見る。

#### 偵察（車両部隊の「偵察」の仕事）

いまの地上部隊は**センサーを持たない**（`radar: null`・§3.2 の最後の項）。「偵察」を役として成り立たせるため、
**(a)＋(b) を両方作る**（2026-09-27・プレイヤーの決め）。

**(a) 地上の目視 `sight` —— 種類ごとの広さで役を分ける。** 地上ユニットは地上の敵だけを見る目視を持ち、
見たものを**陣営のコンタクトに載せる**（地形の見通しは `sim/sight.js` を通す）。

| | 目視（案） | 自分の武器の射程 | 意味 |
|---|---|---|---|
| CONVOY | **8km**（最も広い） | 機銃 0.8km | 見る役。撃つより見る |
| TANK | 3km | 主砲 2.5km | 自分の撃てる所だけ見える |
| ARTILLERY | 2km | 榴弾 4.5km | **射程の半分も見えない** —— 誰かに見てもらわないと射程を使い切れない |

- 見たものは陣営で共有するので、プレイヤーと友軍の司令官の地図に敵の地上部隊が映り、**友軍の攻撃機がそれを目標に取れる**
  （司令官は識別済みのコンタクトしか狙わない＝`_groundTargets`）。
- 敵側も同じ。**敵の車両部隊に見つかると、敵の榴弾砲が届く**。

**(b) 着弾観測 —— 榴弾砲は陣営が見えている相手しか撃たない。**

- 直射の武器（戦車の主砲・機銃）は自分の目視の中の相手を撃つ（射程が目視より短いので、いまと振る舞いは変わらない）。
- **榴弾は陣営のコンタクトにある相手**を撃つ。見ているのは車両部隊でも戦車でも航空機でもよい ——
  **プレイヤーの機体が見た敵にも友軍の榴弾砲が撃つ**。空と地上が噛み合う所。
- 狙うのはコンタクトの位置（真の位置ではない）。航跡の誤差（§54 の `err`）がそのまま着弾のずれになる。
  **見え方の質が当たり方に効く** —— 目視で見続けていれば当たり、見失えば外れる。

**既存の面への影響:** 本編で地上を動くユニットは **COASTAL WALL の車両部隊だけ**（`stages.js:401`）で、
**榴弾砲は本編にもチュートリアルにも置かれていない**（grep で確認）。(b) は既存の面を変えない。
車両部隊に目視が付くと、COASTAL WALL では**敵の車両部隊が自軍の沿岸レーダーを敵側のコンタクトに載せる**ようになる
（敵の司令官は COASTAL WALL では動いていないので、振る舞いは変わらない見込み —— ベンチで確かめる）。
チュートリアル **w1** も車両部隊を的に使っている（`tutorials.js:1250`）ので通しで確かめる。
**自作面（localStorage）に榴弾砲を置いている場合**は動きが変わる（友人の自作面を含め、こちらからは見えない）。

**未確認:** 探知の仕組み（`sim/detection.js`）が地上ユニットを見る側として扱えるか。
いまの見る側は航空機・レーダーサイト・飛行場など。地上の目視を足す場所はこれから調べる。

**移動は変えない。** `_advanceGoal`（どこへ攻めるか）は今までどおりステージが与える情報で動く。
目視はあくまで「撃つ」と「陣営に知らせる」のため。

### 3.3 地上に司令官AIを付けない理由

司令官AIは「1機では決められないこと（誰が誰を護るか・誰がどこへ行くか）」を決める層（§27）。
地上部隊にいま要るのは「どこへ向かうか・いつ止まるか」で、それはステージとトリガーで書ける。
**書き切れない場面が出てから足す**（案は §6 の A4）。

### 3.4 釣り合いの作り方

「地上戦を支援する面」は**空が何もしなければ友軍の地上部隊が負ける（または膠着する）**ように置き、
空からの支援で傾く、が基本の形。その確認のために:

- **道具 `tools/_groundwar.js`**: 航空機を出さずに地上戦だけを回し、決着までの時間・残った部隊・どちらが勝ったかを種ごとに出す。
- 面を作るときは「空なしで友軍が負けるまで N 分」を先に測ってから、敵の空の脅威を置く。

### 3.5 未確認（測ってから書く）

- ~~爆弾・ミサイルの爆風が味方の地上部隊を傷つけるか~~ → **傷つけない**（コードで確認: 爆風 `missile.js` `_blast`・弾丸 `bullet.js:119` とも同じ陣営を飛ばす）。
  地上戦のただ中へ爆弾を落としても味方は無傷。**遊びとしてはこのままでよいか**は Q10。
- `reach` 目標が地上部隊の到達を数えられるか（「友軍の戦車隊が町に着けば勝ち」を書けるか）。

## 4. 勝敗と評価

- 友軍は**プレイヤーの敗北条件に入れない**（Q3 決定）。友軍に守らせたい・生き残らせたいものがある面は、
  いまある `protect` / `hold` 目標にタグで書く（例: 「友軍の戦車を 3両以上残す」＝`hold`）。
- 評価の練度（失った数）は**プレイヤーの指揮下だけ**を数える（Q3 決定）。友軍の損失は結果画面に別の行で出す。
- 敗北「全機を失った」は、プレイヤーの機体が全滅した時点で判定する（友軍機が残っていても負け）。

## 5. 友軍側のトリガー `[A2]`

- `EnemyTriggers` を**陣営と指揮を引数に取る形**へ一般化する（`new SideTriggers(world, side, owner, defs)`）。
  敵側は今までどおり（144戦の指紋一致で確かめる）。
- 条件は今と同じ（`time / detected / destroyed / below / enter / fired`）。**`detected` は友軍側のセンサーに映ったもの**。
- 行動は今の6つ（`guard / defend / restore / launch / reinforce / notice`）に、地上の行動の切り替えを足す:
  `ground` —— 指定タグの地上部隊を `advance / hold / retreat` にする。
- 例: 「敵の防空が壊れたら（`destroyed`）友軍の戦車隊が前進を始める（`ground: advance`）」。
  **プレイヤーの働きが友軍の動きの引き金になる**面が作れる。
- エディタの「トリガー」タブに「敵側／友軍側」の切り替えを足す。
