## 2. P0 撃墜の記録 `[確定]`

- `Unit.damage(amount, source)` で **最後に当てたもの** を `u.lastHit = { by, weapon }` に残す。
  - ミサイル・爆弾 → `by = launcher`, `weapon = 兵装ID`
  - 機銃・対空砲の弾 → `by = 撃った機体・陣地`, `weapon = 'GUN'`
  - 飛行場ごと壊された駐機機 → 飛行場の `lastHit` を引き継ぐ
- 地形・燃料・撤退での死亡は `lastHit` を見ない（`cause` がそれを言う）。**攻撃者が分からないことを「地形」と混ぜない。**
- 記録先: リプレイの `kill` / `loss` イベントに `by`（ID）と `w`（兵装）、playlog のイベントに `by`（名前）・`byType`・`weapon`。
- **AI はまだこれを読まない。** 読ませるとき（P3）は、敵側のセンサーに映っていた攻撃者に限る。

## 3. P1 トリガー `[確定]`

### 3.1 データ

`stage.enemy.triggers` の配列。書かなければ何も起きない（既存の面・ベンチは変わらない）。

```js
enemy: {
  triggers: [
    { id: 'sam_down', label: 'SAM が落ちたら北の飛行場を守る',
      match: 'all',                         // all = すべて満たす / any = どれか1つ
      when: [ { type: 'destroyed', tag: 'sam' } ],
      delay: 0,                             // 成立から実行までの秒数
      do: [ { type: 'defend', tag: 'cap1', base: 'base' },
            { type: 'notice', text: '敵の迎撃機が飛行場へ戻っていく' } ] },
  ],
}
```

- **1回きり。** 成立したら `delay` 秒後に `do` を上から順に実行して終わる。
- 判定は任務の判定と同じ 2Hz（`Mission.update` の中）。本編とベンチの両方で同じ経路を通る。
- 乱数は使わない。条件は `world.units` と探知から作るので、種固定のベンチはそのまま使える。

### 3.2 条件（when）

| type | 欄 | 意味 | 敵が知りうるか |
|---|---|---|---|
| `time` | `seconds` | 開始から n 秒 | ― |
| `detected` | ― | 自軍機が1機でも敵に掴まれた（増援の「見つかってから」と同じ判定） | 探知そのもの |
| `destroyed` | `tag`, `count`（省略で全滅） | **敵側の**そのタグが全滅 / n 個以上壊された | 自分の損害 |
| `below` | `tag`（省略で敵の航空機すべて）, `n` | **敵側の**そのタグの生存数が n 以下。タグの持ち主がまだ1つもいなければ成立しない | 自分の戦力 |
| `enter` | `x`, `z`, `r` | 自軍機が区域に入った。**敵がいま掴んでいる機体だけ**を、敵が見ている位置で数える | センサー |
| `fired` | `id` | 別のトリガーが実行済み（連鎖） | ― |

- `destroyed` / `below` は敵側（赤）のユニットだけを数える。プレイヤー側のタグは見ない —— 敵には、見えていない自軍の損害は分からないため。

### 3.3 行動（do）

| type | 欄 | 意味 |
|---|---|---|
| `guard` | `tag`, `x`, `z`, `alt`（対地高度・省略 5000）, `r`（省略 4500） | その地点に陣取る（GUARD＋持ち場の書き換え＋`guardHome`） |
| `defend` | `tag`, `base`（`base` / `base2`） | 飛行場の上に陣取る（高度は飛行場の上 4000m・半径 6000m） |
| `restore` | `tag` | トリガーが触る前の AI モード・持ち場に戻す（司令官がいる面なら司令官の指揮に戻る） |
| `launch` | `base`, `aircraft`（機種）, `n`, `tag` | その飛行場から今すぐ n 機出す（増援と同じ出し方・同じ搭載） |
| `reinforce` | `base`, `on`（真偽） | その飛行場の増援の時計を動かす／止める |
| `notice` | `text` | 画面のログに状況文を出す（`【状況】…`）。**条件がプレイヤーに見えない問題への手当て** |

- **`guard` / `defend` / `restore` は、その時点で生きている敵機だけに効く（写し取り）。** あとから同じタグで出てくる機体には効かない。
  あとから出す機体を陣取らせたいなら、同じトリガーに `launch` → `guard` の順で書く。
- 帰投中（RTB）の機体は今の帰投を続け、**積み直して上がったあと**に新しい持ち場へ行く。
- 地上ユニットには効かない（航空機だけ）。
- 飛行場が壊れていれば `defend` / `launch` は何もしない。

### 3.4 増援の「トリガーで開始」

増援の開始条件を3通りにする: `after` なし（時計）／ `'detected'`（見つかってから）／ `'trigger'`（`reinforce on` まで待つ）。

- **止まっている増援・まだ始まっていない増援は「これから湧く」に数えない**（§74.3 の `pending`）。
  数えると、トリガーが一度も成立しなかったときに `destroyAll` が永久に達成できなくなる。
  代わりに、**始まる前に同じタグの敵を全滅させれば、その時点で達成になる。** `launch` で出す機体も同じ。
- `reinforce off` で止めた増援は、もう一度 `on` すれば続きから数える。

### 3.5 エディタ

- 下の段に **「トリガー」タブ** を足す。1件ずつ枠に入れて、名前・すべて/どれか・遅らせる秒数・条件の行・行動の行を並べる。
- 条件・行動は種類を選ぶと欄が入れ替わる。タグ・機種・飛行場・別のトリガーは選択肢から選ぶ（打ち間違いで動かない、を防ぐ）。
- 地点を持つもの（`guard` の地点・`enter` の区域）は **地図に印を出して掴んで動かせる**。
- 敵飛行場の増援欄の「見つかってから数える」を、**開始: 時計／見つかってから／トリガーで** の選択に変える。
- `validate()` で拾うもの: 存在しないタグ・飛行場・トリガー ID、地図外の地点、「トリガーで開始」なのに `reinforce on` がどこにも無い増援、ID の重複。

## 5. P3 司令官が機種を選ぶ `[提案・論点を詰める段階]`

プレイヤーの注文: 判断材料は友人の案（撃墜の記録）に限らない。**アイデアが足りていないので、作るならもっと詰める。**
今わかっている制約と、詰めるための論点:

- **制約:** 戦闘中の情報だけ・敵のセンサーに映ったものだけ（決定済み）。
- **論点1 何のために選ぶか。** 「プレイヤーの編成に相性の良い機体を当てる」は面を覚える遊びと相性が悪い。
  代わりの目的の候補: 敵の任務（§73 の protect / destroyAll）の達成に足りない役割を埋める／失った役割を補う。
- **論点2 判断材料の候補。** 見えている自軍機の数と機種・自軍機の進路（どの守り目標へ向かっているか）・
  敵の守り目標が受けている損害・味方の残り（役割ごと）・撃墜の記録（攻撃者が見えていたもの）。
- **論点3 相性の知識をどこに置くか。** 手書きの表なら較正に機種×機種の強制条件の測定が要る（相性は高度などの条件で入れ替わる・§98.7）。
- **論点4 面の難しさ。** 評価の帯はベンチで置いている。司令官の選び方を変えるたびに帯の置き直しが要る。
